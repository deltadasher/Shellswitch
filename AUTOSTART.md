# Compositor-specific autostart

In the TUI, use Tab to open **Autostart**. Left/Right chooses a compositor,
Up/Down chooses a shell, Enter saves, and Delete clears that compositor's choice.
Saving does not switch desktops. Choices persist independently.

Equivalent commands:
- shellswitch autostart --compositor niri --shell tonantzintla
- shellswitch autostart --compositor hyprland --shell caelestia
- shellswitch autostart --compositor hyprland --clear
- shellswitch autostart (launch the saved choice for the current compositor)

Saving installs an XDG desktop autostart entry. Managed Niri resume startup
commands consult these profiles when any profile exists. With no choice for the
current compositor, no other compositor's choice is launched.

The recognized Hyprland generator marked AUTOGENERATED FROM SETTINGS.JSON
is supported by replacing a registered direct Quickshell startup command in
settings.json, with a backup under the state directory's startup-backups.
Its generated .conf files are not edited. Other sessions must execute XDG
autostart entries or call shellswitch autostart from their startup configuration.
Shellswitch does not assume every compositor runs XDG autostart automatically.

A live process in another session is not terminated by profile activation.
Simultaneous independent sessions still share the registry/transaction store;
per-seat concurrent shell management is not implemented. Pending recovery and
emergency holds remain explicit blockers. A dead prior-session process is not a
rollback target. Autostart validates compatibility and uses the switch transaction;
it does not install missing dependencies or invent support for an unknown shell.

The process inventory is refreshed before automatic adoption, and a vanished PID
does not prevent the TUI from opening.
